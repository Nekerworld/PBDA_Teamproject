# v8 타당성 검토: 평가 모집단이 큰 새 데이터의 봉인 시험

- 목적: RetailRocket에서는 평가 사용자가 fold당 수백 명이라 Hybrid와 기본 모델의 차이를 유의하게 보일 수 없었다 (`validation_report.md` §33, `audit/v8dev/power_check.csv`). 평가 모집단이 큰 데이터에서 Hybrid(기존 v1과 v8 재정렬)를 한 번만 여는 봉인 시험으로 확인한다.
- 확인한 것: 데이터 크기와 평가 사용자 수뿐이다 (v7과 같음). 모델을 학습하거나 점수를 낸 것은 없다 (`audit/v8prep/feasibility.py`, `feasibility.json`).
- 원본: `data/taobao/UserBehavior.csv`, `data/diginetica/`. 변환 규칙과 원본 해시는 `dataset_adapters.py`, `audit/v8prep/adapter_*.json`.

## 4. 계산량

- 현재 코드는 평가 사용자마다 카탈로그 전체 점수 벡터를 ALS·BPR·GNN마다 메모리에 둔다. 2%는 시험 1만 명 × 13.7만 상품 × 3 모델로 float64 약 33GB, 5% 이상은 이 PC(64GB)에서 불가능.
- Hybrid grid(2,808개 × backbone 3 × 정책 2)는 v8 개발 D1에서 사용자 145명·카탈로그 약 2.4만에 정책당 약 63초였다. 사용자 수와 카탈로그 크기에 비례한다고 보면 1%의 validation 2,960명·7만 상품에서 약 5–6시간, 2%는 약 24시간.

## 5. 제안하는 v8 설계 (실행 전 사용자 승인 필요)

1. **데이터**: Taobao 1% (seed 42) 한 fold를 주 시험으로. Diginetica는 검정력이 없어 봉인 시험에서 빼거나, 넣는다면 서술 통계만(우월성 판단 없음).
2. **분할·전처리**: v7과 같음 (시험 0.25, validation 0.2, 이벤트 3-core, IF 없음). 재고 신호 없음.
3. **모델과 grid**: v7과 같은 ALS·BPR·GNN grid, seed 42/43/44, ALS+BPR α 11개, 기존 Hybrid(v1) grid 2,808개. 여기에 v8 재정렬 두 설계(`policy_truth`, `weighted`)를 추가. 재정렬은 내부 validation 창(학습 = validation 학습 구간, 라벨 = validation 라벨)에서 학습하고 설정은 그 안의 사용자 단위 5-fold CV로 고른 뒤, 전체 학습 구간으로 다시 학습한 기본 모델 위에서 시험에 적용.
4. **통계**: v7과 같은 쌍대 bootstrap 95% CI와 sign-flip, Holm은 Hybrid 세 가지(v1, 재정렬 두 설계) × 기본 모델 전부 × NDCG·Recall@50을 한 묶음으로. 특징 묶음 ablation(MF만, MF+GNN, 이력 없음 등)은 서술로만.
5. **시험 열람**: 선택을 잠근 뒤 한 번. 사후 분석 없음. RetailRocket v6·v7과 v8 개발 결과는 바꾸지 않음.
