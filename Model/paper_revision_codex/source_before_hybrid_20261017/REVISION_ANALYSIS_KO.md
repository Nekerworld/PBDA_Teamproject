# Revision 분석 및 수정 기록

기준일: 2026-10-16. 대상: IEEE Access, Access-2026-41288.

## 결론

현재 가장 시급한 작업은 모델 성능을 올리는 것이 아니라 논문에 사용할 실험 조건과 결과를 일치시키는 것이다. 기존 가이드의 IF 끔·80:20·409명 학습 사용자 설명을 현재 `data/research_revision_paper` 결과에 적용하면 안 된다. 현재 저장 결과는 IF 켬·80:20이고, 현재 실행 코드 기본값은 IF 켬·90:10이다. 같은 폴더 이름이 같은 실험을 보장하지 않는다.

이 작업은 기존 모델을 새 폴더에 복사한 후 통계표 계산 오류와 출력 경로를 수정하고, 저장 결과의 무결성과 프로토콜을 검증하는 도구를 추가했다. GPU 전체 재학습 및 논문 본문 편집은 수행하지 않았다.

## 현재 결과의 핵심 문제

IF가 학습 구매 17,864건을 전부 제거했다. IF 이후 구매는 0건이고, core 이후에도 0건이다. 장바구니는 최종 학습에 320행만 남는다. 평가 사용자 854명 중 711명은 추천 목록이 없으며 0점으로 집계된다. conditional 정답 사용자는 55명으로, 추천이 존재하는 143명과도 다른 개념이다.

| 모델 | original NDCG@50 평균 | Recall@50 평균 |
|---|---:|---:|
| ALS | 0.005510 | 0.009312 |
| BPR | 0.005960 | 0.006510 |
| ALS+BPR | 0.007319 | 0.009690 |
| LightGCN | 0.006286 | 0.010411 |
| Hybrid | 0.006871 | 0.009859 |

seed 42·43·44 평균이며 표본 표준편차는 `model_summary.csv`에 있다. Hybrid NDCG는 ALS+BPR보다 낮다. 기존 paired_differences.csv의 해당 seed별 NDCG 차이 신뢰구간도 0을 포함한다. 이 자료는 우월성을 뒷받침하지 않는다. 세 seed는 세 독립 데이터셋이 아니므로 사용자 bootstrap과 seed 변동성을 혼동하면 안 된다.

IF 특징: event_count, view_count, unique_visitors, event_code_mean, event_code_std, first_event_hour, last_event_hour, event_duration_hours, property_count. 설정은 n_estimators=200, contamination=auto, random_state=42, max_samples=auto다. 상품 이상치 비율 13.1635%와 이벤트 제거율 62.0541%는 분모가 다르다.

## 구현한 수정

1. `experiments.py`의 통계표 희소도: 이벤트 행 수 대신 `unique_user_item_pairs`를 사용한다. 반복 조회가 많은 데이터에서 원래 계산은 행렬 밀도를 과대평가했다. 평균 이벤트/사용자 통계는 이벤트 수를 계속 사용한다.
2. `data_protocol.py`와 `experiments.py`의 기본 결과 경로를 이 작업 폴더 아래 `results/`로 옮겼다. raw data는 프로젝트의 기존 `data/`에서 읽는다. 기존 결과에 이어 쓰지 않는다.
3. `audit_revision.py` 추가: ML 모듈을 실행하지 않고 AST로 기본값을 읽으며 결과 해시, 실행 완료, 분할, 평가 집합, seed, 통계표 차이를 점검한다. `--strict`는 문제가 있으면 종료코드 2를 반환한다.
4. `test_codex_audit.py` 추가: 반복 이벤트를 포함하는 2×2 행렬에서 희소도가 50%로 계산되는지 실제 표 생성 함수를 실행해 검증한다. 설정 읽기와 해시 변경 감지도 검사한다.

기존 원본 `paper_revision` 및 기존 연구 결과는 수정하지 않았다. LOCKED의 IF 여부나 90:10 기본값도 임의로 바꾸지 않았다. 이미 시험 결과를 확인한 뒤 유리한 조건을 사전 지정한 것처럼 기록할 수 없기 때문이다.

## 다음 실험과 원고 작업

1. 시간 분할 80:20 또는 90:10 중 한 가지와 본실험 IF 여부를 정하고, 기존 결과와 분리된 계획에 변경 이유를 기록한다. IF 없는 조건과 IF 있는 조건은 같은 평가 사용자·정답에서 비교한다. IF 없는 조건을 선택하더라도 선택 시점과 사후 변경 사실을 명시한다.
2. 현재 90:10 코드를 실행한다면 854명을 고정 숫자로 재사용하지 않는다. 새 분할에서 평가 집합과 통계를 다시 산출한다.
3. 전체 공통 분할 평가, IF 비교, gamma 검증 민감도, 후보 recall, 학습·추천 batch 비용을 완결한다. Hybrid가 이기지 않으면 그 결과와 후보 제한을 논의한다.
4. 실제 원고 파일을 확보한 뒤 V-B 분할 설명, LightGCN 설명, Eq.9 gamma, Table 1, Figure 2/4 및 Discussion을 함께 수정한다. 프로젝트에서 확인한 파일 목록에는 원고 원본이 없어서 본문 위치별 수정은 보류 상태다.
5. 심사자별 concern/response/action 및 페이지·행 번호를 채우고, 변경 강조 PDF와 clean 원고·PDF를 준비한다. 메일은 이 세 종류의 재투고 자료를 요구한다. 아직 제출 준비 완료 상태는 아니다.

## 검증 범위

추가 회귀검사는 번들 Python에서 실행한다. 기존 전체 모델 테스트는 scipy, scikit-learn, torch, implicit, pytest가 이 실행 환경에 없어 실행하지 않았다. 합성 테스트나 저장 결과 감사는 실제 RetailRocket 재학습을 대체하지 않는다.
